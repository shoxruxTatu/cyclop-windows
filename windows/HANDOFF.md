# Для Claude Code на Windows-ПК

Этот файл — вводная для сессии Claude Code, открытой на компьютере автора.
Проект начинали на Mac, где Windows-версию можно было только собрать, но не
запустить. Здесь её наконец можно запускать, смотреть и чинить по-настоящему.

## Что это

**Cyclop для Windows** — порт macOS-утилиты Cyclop (MIT, Adil Kalikbergenov):
тонкая чёрная полоска вверху по центру экрана; задержал курсор — раскрывается
панель с вкладками: музыка, полка файлов, буфер, заготовки, календарь (iCal),
перевод, валюта, заметки, суфлёр, утилиты (скриншоты, блокировка клавиатуры),
настройки. C# / WPF / .NET 8, интерфейс собран кодом, без XAML.

Автор Windows-версии: @shoxrux.edit (Instagram). Пишем ему по-русски.
Нужна только PC-версия — macOS-код в `Sources/` не трогаем.

## Где что

- Репозиторий: https://github.com/shoxruxTatu/cyclop-windows (публичный).
- `windows/Cyclop.Core` — всё без Windows (хранилища, iCal, валюты, перевод,
  обновления, локализация) + тесты в `windows/Cyclop.Core.Tests`.
- `windows/Cyclop` — приложение: `Panel/` (окно панели, наведение, мониторы,
  скриншоты), `Panes/` (вкладки), `Services/` (медиа, буфер, полка, горячие
  клавиши, обновления, блокировка), `App/` (запуск, трей, окно отзывов).
- `windows/server` — Cloudflare Worker: обновления, статистика, отзывы.
  Живёт на https://cyclop-updates.cyclop-updates.workers.dev
  (`/v1/check`, `/download`, `/v1/feedback`, `/stats`, `/feedback`).
  **Адрес вшит в выпущенные exe — поддомен и имя воркера не менять.**
- `windows/site/public` — сайт https://cyclop.cyclop-updates.workers.dev.
  Выкладывается `npx wrangler deploy` **из папки `windows/site`** (не из
  `server` — там другой конфиг).
- Подробности: `windows/README.md`, выпуск версий: `windows/RELEASING.md`.

## Как собрать и запустить

```powershell
dotnet test windows/Cyclop.Core.Tests
dotnet run --project windows/Cyclop
```

Локальная сборка **не обновляется и не шлёт статистику/отзывы**: адрес
сервера вшивается только в релизных сборках (`-p:UpdateServer=…`). Чтобы
проверить обновления или отзывы локально, соберите с ним:

```powershell
dotnet run --project windows/Cyclop -p:UpdateServer=https://cyclop-updates.cyclop-updates.workers.dev
```

Если уже запущен Cyclop из релиза, новая сборка закроет его сама (одна копия
за раз). Журнал программы: `%APPDATA%\Cyclop\log.txt` — туда пишутся
медиасессии, горячие клавиши, шаги скриншота, проверки обновлений, ошибки.

## Выпуск версии

Метка `win-vX.Y.Z` → GitHub Actions (`.github/workflows/windows-release.yml`)
собирает exe x64/arm64 с вшитым адресом сервера и публикует релиз. Описание —
заранее в `windows/releases/win-vX.Y.Z.md`. Метки `v*` — это macOS, не трогать.
Публиковать (push метки, deploy) — **только после явного «да» автора**.

## Открытые вопросы на момент передачи (3 ноября 2026)

1. **Автообновление 0.9.1 → 0.9.2 ещё не проверено вживую.** Сервер видит
   установку 0.9.1 (Windows 11 26200, x64) и раздаёт 0.9.2. В 0.9.1 проверка
   раз в 6 часов, поэтому обновление не пришло сразу. Проверить: Настройки →
   Обновления → «Проверить», затем `log.txt` (строки `update check`,
   `update:`/`update failed`). В коде (ещё не выпущено) проверка уже раз в
   час + повтор через 5 минут, если панель открыта.
2. **Музыка:** в 0.9.2 Cyclop слушает все медиасессии. Проверить с YouTube в
   Яндекс Браузере при нескольких вкладках со звуком; пауза/следующий трек
   (там запасной путь через медиаклавиши).
3. **Скриншоты** (Ctrl+Alt+A область: ЛКМ — в буфер, ПКМ — редактор;
   Ctrl+Alt+S — экран) ни разу не проверялись на реальном Windows.
4. **Сайт выглядит «макетом»**: демонстрация панели нарисована CSS. Нужны
   настоящие снимки программы (музыка, полка, редактор скриншотов, буфер) и
   короткое видео раскрытия панели — их можно снять здесь, затем вставить в
   `windows/site/public` вместо нарисованной демонстрации.

## Чего здесь нет (и не нужно коммитить)

- Пароль админки — у автора (он его менял).
- Входы `gh` и `wrangler` — если нужно публиковать с этого ПК:
  `gh auth login`, `npx wrangler login` (в папке `windows/server`).
- Папки `.wrangler/`, `node_modules/`, `windows/dist/` — в `.gitignore`;
  проверять `git status` перед коммитом.
