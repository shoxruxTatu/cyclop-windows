# Обновления и статистика: как запустить и как выпускать версии

Схема: **GitHub** хранит код и релизы, **Cloudflare Worker** (`windows/server`)
отвечает программам «какая версия последняя» и считает пользователей.
Оба бесплатны. Настройка — один раз, около получаса.

```
Cyclop.exe ──раз в 6 часов──▶ Worker ──читает релизы──▶ GitHub Releases
                                │
                                └─ записывает «установка N жива сегодня» ─▶ база D1
Вы ──▶ https://…workers.dev/stats (пароль) ──▶ графики
```

## 1. Репозиторий на GitHub

1. Зарегистрируйтесь на <https://github.com> и создайте репозиторий, например
   `cyclop`. Он должен быть **публичным**: программы скачивают обновления без
   пароля, а файлы приватных релизов без него не отдаются.
2. Выложите туда эту папку (терминал, в корне `cyclop-main`):

```bash
git init -b main
```

```bash
git add . && git commit -m "Cyclop for Windows"
```

```bash
git remote add origin https://github.com/ВАШ_ЛОГИН/cyclop.git
```

```bash
git push -u origin main
```

## 2. Сервер на Cloudflare

1. Зарегистрируйтесь на <https://dash.cloudflare.com> (бесплатный план).
2. В терминале, в папке `windows/server`:

```bash
npm install
```

```bash
npx wrangler login
```

Откроется браузер — подтвердите вход.

```bash
npx wrangler d1 create cyclop-stats
```

Команда напечатает `database_id`. Откройте `windows/server/wrangler.toml` и
впишите:
- `database_id` — это значение;
- `GITHUB_REPO` — `ВАШ_ЛОГИН/cyclop`.

Создайте таблицу и задайте пароль страницы статистики (его спросит
терминал, он хранится в Cloudflare, а не в файле):

```bash
npx wrangler d1 execute cyclop-stats --remote --file schema.sql
```

```bash
npx wrangler secret put STATS_PASSWORD
```

```bash
npx wrangler deploy
```

В конце `deploy` напечатает адрес вида
`https://cyclop-updates.ВАШ_ПОДДОМЕН.workers.dev` — это адрес сервера
обновлений.

## 3. Связать GitHub с сервером

В репозитории на GitHub: **Settings → Secrets and variables → Actions →
Variables → New repository variable**:

- Name: `UPDATE_SERVER`
- Value: адрес из прошлого шага (`https://cyclop-updates….workers.dev`)

Без этой переменной релиз не соберётся — workflow остановится и скажет почему.

## 4. Выпустить версию

Версия берётся из метки. Например, 0.9.1:

```bash
git tag win-v0.9.1 && git push origin win-v0.9.1
```

GitHub Actions (вкладка **Actions**) за ~10 минут соберёт exe для x64 и ARM,
посчитает SHA-256 и опубликует релиз «Cyclop для Windows 0.9.1».
Описание релиза можно заранее положить в `windows/releases/win-v0.9.1.md` —
иначе GitHub составит его из коммитов.

Дальше всё само: программы спрашивают сервер через 20 секунд после запуска
и раз в 6 часов, скачивают новую версию, сверяют SHA-256 и перезапускаются.
Если пользователь в этот момент работает с панелью, делает скриншот или
клавиатура заблокирована — обновление ждёт следующей проверки.
Каждая следующая версия должна быть больше предыдущей: `win-v0.9.2`,
`win-v0.10.0`, `win-v1.0.0`.

**Важно про первую раздачу.** Обновляться умеют только сборки из релизов —
в них вшит адрес сервера. Exe, собранные локально (`windows/dist`), сервер
не знают. Поэтому пользователям давайте ссылку на страницу релизов:
`https://github.com/ВАШ_ЛОГИН/cyclop/releases`.

## 5. Смотреть статистику

Откройте `https://cyclop-updates….workers.dev/stats`. Браузер спросит логин и
пароль: логин любой, пароль — тот, что задали в `STATS_PASSWORD`.

На странице:
- уникальные пользователи сегодня, за 7 и 30 дней, всего;
- график пользователей по дням и новых установок по дням;
- какие версии стоят у людей и сколько x64 / ARM.

«Пользователь» здесь — установка, которая хотя бы раз за день спросила об
обновлении. Кто выключил подсчёт в настройках, не считается.

## Что и сколько стоит

Бесплатного плана Cloudflare (100 000 запросов в день) хватит примерно на
20 000 ежедневных пользователей: каждая программа обращается к серверу до
4–5 раз в сутки.

## Приватность

Что отправляет программа: свою версию, архитектуру (x64/ARM), версию Windows
и — если подсчёт включён — случайный номер установки, созданный при первом
запуске. Сервер хранит строку «номер, день, версия, архитектура, версия
Windows». IP-адреса, имена, файлы, содержимое буфера и всё остальное не
отправляются и не хранятся. Пользователь видит это при первом запуске
(уведомление в трее) и может выключить подсчёт в Настройках → Обновления;
обновления при этом продолжают работать.

## Подпись exe (по желанию)

Неподписанный exe при первом скачивании через браузер пугает SmartScreen
(«Подробнее → Выполнить в любом случае»). Обновления, которые программа
скачивает сама, этого окна не вызывают. Чтобы убрать его и при первой
установке, нужен сертификат подписи кода — например, Azure Trusted Signing
(около $10 в месяц); его подключают к этому же workflow.
